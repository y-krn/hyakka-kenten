# 百科拳典（ひゃっかけんてん）

Wikipediaの記事が、事実だけで殴り合う。

**遊ぶ：https://hyakkakenten.com/**

日本語版Wikipediaの記事を2つ選ぶと、WikidataとWikipediaに載っている事実（高さ・人口・作品数・言語版の数など）だけで、真面目に戦います。

## 遊び方

1. 記事名を2つ入れる（または「おまかせで組む」）
2. 「対戦開始」
3. 結果をコピーして共有する

同じ組み合わせなら、誰が何度やっても同じ結果になります。

## 王座戦

いまの王者記事に、好きな記事で挑めます。勝てばその記事が新しい王者になり、挑戦した人の名前が残ります。勝敗はサーバー側（`worker/`）でもページと同じ計算をし直して決めるので、結果をごまかすことはできません。

- 結果は何度やっても同じなので、同じ組み合わせの王座戦は一度きりです（どちらが王者だったかは問いません）
- 挑戦はブラウザ1つあたり10分に10回、1日に100回まで（同じ回線全体では10分に60回まで）
- 名前は16文字まで。使えない言葉があります
- 記事データ（`data/`）と戦闘の計算（`index.html`・`worker/src/engine.mjs`）はすべて公開しています。手元で計算して勝てる記事を探すのも、攻略のうちです

## 収録している記事

- 2026年10月18日時点の日本語版Wikipediaの記事のうち、約140万記事
- 次のものは収録していません
  - 一覧・曖昧さ回避のページ
  - 災害・事故・事件・テロなど、人が亡くなった出来事（1900年以降）
  - 犯罪に関わる人物、最近亡くなった人物
- 判定しきれなかった記事は「確認中」として、対戦に出していません

## おかしな内容を見つけたら

対戦結果の下にある「この対戦の内容が不適切だと思ったら知らせる」から、このリポジトリのIssueで知らせてください（GitHubのアカウントが必要です）。確認して、必要なら `data/exclude.json` に記事名を足して収録から外します。

### 不適切な名前を消す（管理者向け）

```sh
curl -X POST https://<APIのURL>/api/admin/hide -H "Authorization: Bearer <ADMIN_TOKEN>" -H "Content-Type: application/json" -d '{"challenge": 挑戦のID}'
# 王者の名前は {"reign": 王者のID}
```

## 記事を追加してほしいとき

[Issueの「記事の追加リクエスト」](../../issues/new?template=add-article.yml)から記事名を送ってください。管理者が確認して「追加OK」のラベルを付けると、GitHub Actionsが自動で取り込み、結果をIssueに書き込みます。

- 一覧・曖昧さ回避のページや、扱わない題材は追加できません
- できたばかりの記事は、Wikidataの項目が付くまで追加できないことがあります

## データの出典とライセンス

- **Wikidata**（CC0）：数値・関係などの事実
- **日本語版Wikipedia**（CC BY-SA 4.0）：記事名、カテゴリ名、節の見出し名、記事の長さ・リンク数・画像数などの数量
- **Wikimediaの閲覧数データ**（CC0）

記事の本文は使っていません。各記事の内容は、それぞれのWikipediaの記事・Wikidataの項目を確かめてください。数値はWikidataに記録されているもので、実際の総数とは限りません。

## アクセス解析

訪問数などを知るために、Cloudflare Web Analytics を使っています。Cookieは使わず、個人を特定する情報も集めません。

## お断り

百科拳典は個人が作った非公式のゲームです。Wikipedia・WikidataおよびWikimedia Foundationとは関係がなく、提携や承認も受けていません。WikipediaはWikimedia Foundationの登録商標です。

対戦はすべて、記録された事実をもとにした冗談です。記事の対象となっている人物・団体・物事をおとしめる意図はありません。

## 公開のしくみ

ゲームの画面・記事データ・王座戦APIは、すべて1つの Cloudflare Worker（`worker/`）から https://hyakkakenten.com に配っています。`main` に push すると GitHub Actions（サイトとAPIのデプロイ）が自動で反映します。

- 画面は `tools/mk_site.py` で作る：`HK_API=same python3 tools/mk_site.py <元のページ> index.html`（`worker/src/engine.mjs` も一緒に書き出されるので、`worker/src/` にコピーする）
- 共有URL（`?c=挑戦の番号` / `?a=記事&b=記事`）で開かれたときは、Workerが共有カード（OGP）の文字だけをその試合用に書き換える
- 「あなたの代表戦」の一覧（`data/bd/`：誕生日・生まれた年・出身地ごとの人物）は `tools/build_bd.py` で作る。**記事データを丸ごと作り直したときは、Actions の「代表戦の索引を作る」も実行する**（ブランチは `main`、約40分。時間の大半は Wikidata への問い合わせ）。記事の追加だけでは更新しないので、追加した記事は次に作り直すまで代表の候補に出ない
- 数値の訂正表（`data/fix.json`）：Wikidata の明らかな誤りを、出どころを確かめたうえで直す。1件ごとに正しい値・「出典」・「確認日」を書く（例：富士山の標高）。数字の項目名は 標高・高さ・重さ・面積・人口・長さ・深さ・速さ。値を null にすると、その数字を使わない（誤った値しかないとき）。「職業」も直せる（文字で置き換え、null で出さない）。保存すると自動でデプロイされる
- 動作確認に使うブラウザは、一度 `https://hyakkakenten.com/?nostat=1` を開いておく。そのブラウザでは Cloudflare Web Analytics を読み込まず、利用回数（/api/plays）も送らないので、確認で数字が水増しされない（`?nostat=0` で外す。プレビューも同じ）
- 対戦に戻す一覧（`data/unhold.json`）：データを作るときに「確認中」（保留）になった記事のうち、確かめて問題ないものを対戦に戻す。`{"記事": {"記事名": "確かめた理由（日付）"}, "理由": {"保留の理由（年の括弧を除く）": "確かめた理由（日付）"}}`。保留の記事を理由ごとにまとめた一覧は `node tools/check/holds.mjs`（手元で動く）。書き換えたら、記事名の候補に出るように索引も作り直す（`python3 tools/build_titles.py data && python3 tools/build_ngram.py data`）。戻した記事も、今日の一戦・ランダムに出したくないなら `data/norand.json` にも書く。利用者の報告による停止（/api/holds）はこれとは別で、戻した記事にも効く。2026-11 の見直しで見つかった誤り（記事名の一部に「テロ」が入るだけの語、作品の題名の「事件」「殺人」、架空の人物、気象・火災・防災の現象や仕組みのカテゴリ）は `tools/gen_v2.js` の判定でも直したので、作り直した後は保留にならない
- 自動の訂正表（`data/fixa/<番号>.json`）：日本語版の記事の情報欄から確実に読めた数字が Wikidata と違うとき、日本語版の値に合わせる（遊ぶ人が「記事を読む」で開く記事と数字をそろえるため）。作り方：「数字の照合」ワークフロー（`.github/workflows/numcheck.yml`）を、よく読まれている順に分けて回し、実行記録の「NC」で始まる行を取り出して `python3 tools/fixa_build.py 結果.jsonl ...`。日本の都道府県・市区町村の人口と面積は、記事が「自治体人口」「自治体面積」テンプレートから数字を引いているので、`tools/check/jpmuni.mjs`（調査用ワークフローで実行）で別に照合し、その結果も渡す。「読み取り不確か」は `tools/check/numtriage.py` でふるい分けてから渡す。手で書く `data/fix.json` のほうが優先。データを作り直したときは、照合もやり直す。Wikidata に同じ数字が複数あるときの選び直し（人口と面積は、2000年以降の時点の付いた値のうち、いちばん新しいもの）は `tools/check/latest.mjs`（調査用ワークフローで、`offset` と `n` で4つに分けて実行）の「LT」の行を一緒に渡す。日本語版で確かめられた項目は、日本語版の値が優先。作り直し用の `tools/gen_v2.js` / `gen5.js` も同じ選び方なので、作り直した後は選び直しは不要（照合はやり直す）
